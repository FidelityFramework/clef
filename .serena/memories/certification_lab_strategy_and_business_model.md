# Certification Lab Strategy and Business Model

> **Created**: February 2026
> **Context**: Go-to-market strategy using CC/safety-critical certification labs as distribution channel.

## The Strategy

Provide Keystone/Atelier to Common Criteria and safety-critical certification labs (CCTLs, NIAP-approved labs, TÜV, etc.) for free evaluation use, then license commercially when labs build bridge tooling on the platform. Labs become the distribution channel into every product developer seeking certification.

## Dual License Structure

**Free for evaluation work**: Labs use Atelier to evaluate products built in Keystone. This costs nothing and creates:
- Lab fluency in Keystone's compilation model
- Firsthand experience with traceability quality
- Organic recommendations to product developers ("your evaluation would be easier in Keystone")
- Labs as an unpaid sales channel to every developer seeking certification

**Licensed for bridge tooling / custom integrations**: When labs build their own tooling on top of Keystone's pipeline (custom report generators, evaluation management integrations, automated evidence extractors), that's a commercial license.

## The Ferrocene Model Inverted

Ferrocene charges developers to use a qualified compiler, then charges more for certification assistance. Keystone gives labs the tool for free, charges when they build commercial capabilities on it, and the labs drive developer adoption as a side effect.

Ferrocene pricing reference (Feb 2026):
- Individual: €25/seat/month (compiler only, no qualification docs)
- Enterprise: custom pricing (qualification signatures, assessor reports, target enablement, certification assistance)
- Key insight: qualification documents are enterprise-only, meaning certification-seeking customers MUST go enterprise

## The Network Effect / Flywheel

1. Labs get Atelier free → learn the tooling
2. Labs evaluate Keystone-built products → see the traceability advantage
3. Labs recommend Keystone to product developers → developer adoption grows
4. More Keystone products need evaluation → labs invest in bridge tooling
5. Labs license bridge tooling commercially → revenue AND deeper lab investment
6. Labs with custom tooling become more efficient → prefer evaluating Keystone products → stronger recommendations

Labs are gatekeepers of certification. Their recommendation carries more weight than marketing.

## What Labs Need vs. What Keystone Provides

| Lab need | Current approach | Keystone/Atelier |
|---|---|---|
| SFR-to-code traceability | Manual spreadsheets | PSG nodes with source ranges through every phase |
| Data flow analysis | Static analysis tools (limited, false positives) | Graph-native: PSG IS the data flow; purity means no hidden information flows |
| Code review of generated output | Manual side-by-side reading | Pipeline Inspector: Source → PSG → MLIR → Assembly, bidirectional |
| Evidence generation | Manual ETR writing | Compilation produces traceability artifacts automatically |
| Proof of correctness | Testing + review (expensive) | Proof-carrying compilation, machine-checked |

## CC-Specific Advantages

### EAL 5+ Semiformal Verification
Most products stop at EAL 4 because semiformal and formal methods are expensive to produce manually. Proof-carrying compilation makes EAL 5-7 tractable because proofs are generated by the compiler.

### TOE Security Domain Mapping
CC evaluation decomposes the Target of Evaluation into security domains with controlled interfaces. Actors with BAREWire message contracts IS that decomposition. The security architecture IS the program architecture.

### Covert Channel Analysis
CC evaluations at higher EALs require covert channel analysis (proving information can't leak through timing or resource usage). Flow loss analysis directly relates: serialization points are potential timing observation points. The flow loss metric quantifies where timing-based covert channels could exist.

## Nanopass Economics for Target Qualification

Ferrocene's "target enablement" (qualifying the compiler for a new platform) is expensive because rustc+LLVM is monolithic. For Keystone:
- Shared infrastructure (FNCS, Baker, nanopasses, PSG elaboration) qualifies once
- Each Alex substrate backend qualifies independently
- Adding a new target (e.g., Tenstorrent RISC-V mesh) means qualifying only that backend
- Target enablement at a fraction of Ferrocene's cost due to modular architecture

## Revenue Streams

1. **Lab bridge tooling licenses** - labs building custom evaluation tools on Keystone
2. **Developer toolchain licenses** - Ferrocene-style per-seat for qualified toolchain
3. **Target enablement** - qualifying new Alex backends for customer-specific hardware
4. **Certification artifacts** - qualification signatures, assessor reports (like Ferrocene Enterprise)
5. **Training** - lab evaluator training, developer training for safety-critical Keystone
6. **Certification assistance** - consulting for program-level certification
