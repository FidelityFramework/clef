# Types as ranges: the designed theory and its status

Sources are ranked by the owner's authority order: arXiv papers first, the spec second, site content third, research notes directional only. Status labels: normative, design-decision, design-sketch, research, aspirational, implemented-claim, not-yet-specified. Every quote is verbatim and at most 300 characters. A source that says nothing is marked silent.

## T1. What a range-typed value is, and the point type as its degenerate case

**What the corpus designs.**

A range-typed value is a numeric value whose type carries a closed interval `[a, b]` beside its dimension. The paper fixes the object and its relation to representation. `/home/hhh/repos/arxiv-papers/dts-dmm-paper.md`, §2.6, line 149: "given a value $v$ with dimension $d$ and a value range $[a, b]$, and a set of available representations $R = \{r_1, \ldots, r_k\}$ on target $T$, the compiler restricts attention to the covering set". Normative.

Dimension and range are two components. Same paper, §2.6, line 157: "The dimensional algebra establishes the kind of quantity; the concrete value range must be supplied by one of three sources." Normative. The spec restates it as its unifying observation. `/home/hhh/repos/clef-lang-spec/spec/numeric-selection.md`, §1, line 16: "the dimensional range, not the dimension, is the input to selection." Normative.

The point representation is not part of type identity. dts-dmm-paper.md, §1.3, line 45: "the type carries the physical semantics while the representation (posit width, float format, fixed-point configuration) is resolved independently per target." Normative.

The spec's integer chapter admits the point as the degenerate interval. `/home/hhh/repos/clef-lang-spec/spec/width-inference.md`, §2, line 22: "**Literals** are point intervals: `124` has range `[124, 124]`." Normative. This is the only normative statement in the corpus that a point is a width-zero range.

The open integer type is a range awaiting a width. `/home/hhh/repos/arxiv-papers/fixed-point-scaffolding.md`, §4, line 71: "| TInt (IntWidth 0) ->                                 // representation not yet fixed". Implemented-claim. And Appendix C, line 311: "The interval analysis records a range for each value, and the width follows from the range". Implemented-claim, scoped to the FPGA pathway.

Bare `float` is the range-silent case, not the default representation. `/home/hhh/repos/clef-lang-spec/spec/native-type-universe.md`, line 176: "`float` and `float32` are the **bare, no-locality-claim** real types: a value with no analyzed range whose representation is not being selected." Design-decision.

A range claim is content, not free type structure. fixed-point-scaffolding.md, §6, line 186: "An inequality $a \le x \le b$, a statement about a distribution, and a relation between two runs are past it, because parametricity is silent about which specific values the variables take". Normative. Same reading in `/home/hhh/repos/arxiv-papers/research/ohori-proof-theory-and-our-tier-architecture.md`, line 44. Design-decision, directional.

A range is not a refinement predicate in the DTS core. dts-dmm-paper.md, §2.4, line 125: "| Expressiveness | Decidable algebraic constraints (abelian groups, enum sorts, bitvectors) | Arbitrary predicates over values |". Normative. The spec nevertheless names refinement lineage. numeric-selection.md, line 20: "Numeric selection inherits the range-as-refinement discipline from **F\***". Normative lineage note.

A distinct object exists: the interval enclosure as a value type. `/home/hhh/repos/clef-lang-spec/spec/rounding.md`, §3.1, line 44: "Interval<r>  is well-formed only if  r  supplies directed rounding". Normative. This is a runtime interval value, not a ranged type, and must not be conflated with the range carried on a type.

**What it leaves open.** Error bounds as type content: `/home/hhh/repos/arxiv-papers/research/approximation-contracts/README.md`, §6, line 108: "What is the type of one? A bound plus a metric plus a domain of validity? Is it a coeffect in the sense the framework already uses?" Research. Constraint manifolds as joint ranges: `/home/hhh/repos/arxiv-papers/research/fabric-inference/07-joint-numeric-representation.md`, §8, line 172: "Selection is over `M ⊂ ℝⁿ` — the constraint manifold — rather than a product of intervals." Research. The point real as `[a, a]` is not stated for reals; width-inference.md states it for integers only. Posterior as type content is T5.

**Tensions.** dts-dmm-paper.md Appendix C, line 814 says "dimensional inference determines the value range". The same paper's §2.6, line 157 says the range "must be supplied". The site post repeats the appendix form at `/home/hhh/repos/clef-lang-site/hugo/content/blog/beyond-the-bitter-lesson-structural-convergence.md`, line 72: "Dimensional inference also determines the value's range". Resolved by authority order within the paper: §2.6 is the normative statement, the appendix and the site compress it.

## T2. Composition: arithmetic, comparison, conversion, application, generalisation; unified or propagated; containment

**What the corpus designs.**

Ranges are propagated, never unified. dts-dmm-paper.md, §2.6, line 157: "a dimensional instantiation at a call site combined with the domain constraints on its arguments produces a range for the computed result, which propagates through subsequent operations." Design-decision. The multiplication rule: §2.2, line 88: "the range of the result is bounded by the product of the input ranges". Design-decision.

The spec gives the integer rules. width-inference.md, §2, lines 23 to 25: "**Arithmetic** propagates intervals: `x + y` has range `[a_x + a_y, b_x + b_y]`; products, shifts, and so on follow standard interval arithmetic." and "**Comparisons seed ranges**: a value compared against a `threshold` is bounded by that threshold on the relevant branch" and "**Recurrences and counters** are bounded by their modulus or termination condition". Normative.

The real domain is a new abstract domain with outward rounding, sign-split reciprocal, transcendentals on monotone segments, and a threshold widening. numeric-selection.md, §9.1, line 226: "`1/[lo, hi]` where the interval contains zero splits into two unbounded pieces". Design-decision. The widening thresholds are the target's format boundaries; same section: "The thresholds SHALL be the dynamic-range boundaries `±dynrange(r)` of the target's concrete format set". Design-decision. The dependency problem is named: rounding.md, §4.3, line 86: "`r·r` over `[a, b]` yields `[min(a², ab, b²), max(...)]`, which includes negatives when `[a, b]` straddles zero". Normative.

Function application through a nonlinear function uses the generic interval rule and may widen. ohori-proof-theory-and-our-tier-architecture.md, line 150: "the generic interval rule for the exponential returns a bound too wide for the window, and the framework reports a conservative finding." Design-sketch, directional.

Conversion is a coverage check with tracked fidelity. width-inference.md, §7, lines 68 to 69: "a lossless transfer is fidelity `1.0`; a lossy one is `< 1.0` with a bound derived from the range" and "A conversion whose target cannot hold the source range is rejected at compile time." Normative. The paper agrees: dts-dmm-paper.md, Appendix C, line 812: "A transfer in the opposite direction (float64 → posit32) would show fidelity $< 1.0$ with a precision loss estimate derived from the dimensional range." Design-sketch.

Family placement. The two families are group and lattice. `/home/hhh/repos/arxiv-papers/decidable-by-construction.md`, §2, line 39: "The group-structured axes support cancellation through inversion, and the lattice-structured axes resolve by ordering." Normative. The spec admits the split. `/home/hhh/repos/clef-lang-spec/spec/grade-discipline.md`, line 206: "The two families range over disjoint sets of constraint variables. They are therefore discharged as two independent queries". Normative. Width is placed in the lattice family by the research note only. `/home/hhh/repos/arxiv-papers/research/grade-axis/02-annotation-disciplines-and-the-unification-substrate.md`, §2, line 24: "| Width | Bounded interval domain over $\mathbb{Z}$ | No | Meet-directed | QF_BV |". Design-decision, directional. Principality on that family is a fixed point, not a unifier. Same note, §7.1, line 87: "principality means most general unifier on the group axes and least fixed point on the lattice axes, each in its native sense." Design-decision, directional.

Containment is a coverage check, not subtyping. The paper's relation is `dynrange(r) ⊇ [a, b]`, dts-dmm-paper.md, §2.6, line 149. The spec's tier composition is precedence, not intersection. numeric-selection.md, §3.4, line 95: "**The binding range is the claim of the highest present tier** (`R₃` if present, else `R₂`, else `R₁`). Higher tiers *override*; they do not silently merge." Design-decision. Line 96: "the compiler checks containment `R_lower ⊆ R_binding` (within a tolerance; see §11)". Design-decision. The PHG paper gives the same shape for support at a boundary. `/home/hhh/repos/arxiv-papers/program-hypergraph-paper.md`, §9, line 482: "a sender's derived support is required to lie within the declaration, widening to the declared mask is sound in the containment direction". Design-decision.

**What it leaves open.** Generalisation of a ranged binding under let-polymorphism: silent in every source. Comparison of two ranged values as a typing rule: silent beyond the branch-seeding rule. Containment tolerance: numeric-selection.md, §14, line 335: "Whether containment `R_lower ⊆ R_binding` is exact or within an ε, and whether the tolerance is per-dimension, is open". Not-yet-specified. Whether real ranges join the lattice family or form a third family: the grade-axis note places integer width only, and states at line 71 that its figures are specification-level widths, not storage. The admission criterion any new axis must meet is decidable-by-construction.md, §8, line 319: "properties expressible that way, whether resolved by abelian-group unification or by lattice ordering, are in the fragment". Normative.

**Tensions.** The PHG paper names set-valued constraints as outside the equality vocabulary and lists two admission routes it declines for grade, program-hypergraph-paper.md, §8.3, line 392: "decompose it into a disjunction of equality constraints, each corresponding to a use context that collapses the set to a point, or extend the underlying theory to first-class set-valued integer constraints". The grade-axis note answers with directed propagation. The paper is authority; the note is the working correction and the metatheory it needs is still open, note 02, §7.3, line 99: "Decidability, completeness, and principality for the joint discipline over real programs remain the named obligations".

## T3. Numeric selection, width, signedness, seals, platform ranges, unobservable ranges

**What the corpus designs.**

The selection objective. dts-dmm-paper.md, §2.6, line 152: "r^* = \arg\min_{r \in R_{\mathrm{cov}}} \max_{x \in [a,b]} \frac{|x - \operatorname{round}_r(x)|}{\max(|x|, \operatorname{ulp}_{\min}(r))}". Normative. The spec restates it with the two side conditions as part of the objective. numeric-selection.md, §2.1, line 50: "R_{\mathrm{cov}}(T, [a, b]) = \{\, r \in R(T) \;:\; \mathrm{dynrange}(r) \supseteq [a, b] \,\}". Normative. §2, line 34: "**Accuracy-only objective.** The score is worst-case error over the range. There is no cost, latency, or area term." Design-decision.

Width and signedness from the range. width-inference.md, §3, line 33: "\mathrm{width}([a, b]) = \begin{cases} \lceil \log_2(b + 1) \rceil & a \ge 0 \quad (\text{unsigned}) \\ 1 + \lceil \log_2(\max(|a|,\, b + 1)) \rceil & a < 0 \quad (\text{signed}) \end{cases}". Normative. Line 14: "a value's range determines whether it is signed or unsigned (§3), so a representation is never selected by a target type name independent of the range the value actually occupies." Normative.

Width and representation are one coeffect read at lowering. width-inference.md, §5, line 58: "The width-inference coeffect holds the range; the lowering pass that fixes the integer representation reads it and writes the chosen width into the operations it produces." Normative. The paper agrees: fixed-point-scaffolding.md, §4, line 78: "the lowering patterns pull those decisions and write them into the operations they produce without recomputing them." Normative.

Seals. A seal is a written representation read as a range claim and checked by reverse selection. numeric-selection.md, §3.3, line 88: "Tier 3 is **sealing**: it converts the argmin from a chooser into a checker (the §2.1 coverage check on a singleton `R`)." Design-decision. §3.4, line 94: a sealed annotation "fixes a representation *and* implies its dynamic range as a range claim". Design-decision. §13, requirement 9, line 324: "A Tier-3 seal SHALL be honored when it covers the range; a covering-but-suboptimal seal SHALL compile and SHOULD be witnessed at design time". Normative. The paper has the same check without the word. dts-dmm-paper.md, §2.6, line 173: "the dimensional constraints can verify that the posit's dynamic range encompasses the expected value range." Design-decision. Explicit selection is sovereign: native-type-universe.md, line 182: "Explicit developer selection of a precision and range is sovereign over inference." Design-decision.

Platform-supplied ranges. The platform supplies the candidate set and each candidate's dynamic range. dts-dmm-paper.md, §2.6, line 159: "its inputs are properties of the PSG (dimensional annotations and platform bindings)". Normative. The spec seats capability facts on the platform. numeric-selection.md, §9, item 6: "**Platform capability facts**, the natural seat for "does this target have native posit hardware, an extended posit instruction, or quire support?"". Design-decision. Widening thresholds are the platform's format boundaries, §9.1, line 226. Design-decision.

Unobservable ranges. Integers: width-inference.md, §6, line 62: "It reports an error asking the source for an annotation." Normative. FPGA diagnostic: fixed-point-scaffolding.md, §4, line 74: "error FPGA0001: range unobservable; the source must annotate the width". Implemented-claim. Reals split on dimensionedness. numeric-selection.md, §6, lines 155 to 156: "**Dimensioned real with unobservable range → ERROR.**" and "**Bare `float` with unobservable range → IEEE `f64`, no error.**" Design-decision. The obligation crystallises at the dimensioning site, §6.1, line 170. Design-decision.

Empty coverage. numeric-selection.md, §2.1, line 52: "**if `R_cov = ∅`, that is a hard error**". Design-decision.

Per-component selection inside aggregates is admitted. grade-discipline.md, line 220: "The representation of each coefficient is selected independently by [Numeric Selection](numeric-selection.md) from that coefficient's analyzed range". Normative.

**What it leaves open.** Seal syntax, see T6. The Tier 2 library binding contract: numeric-selection.md, §4, line 103: "`Fidelity.Physics` is **planned, not built.**" Design-sketch. Profiling provenance: §14, line 336: "whether a profiling range is Tier 1 (with an evidence-provenance tag) or its own tier is unresolved." Not-yet-specified. Parameterisation above format selection: 07-joint-numeric-representation.md, §5, line 126: "**This is the layer `numeric-selection.md` does not currently have.**" Research. Algebraic-form selection above that: `/home/hhh/repos/arxiv-papers/research/fabric-inference/08-representation-levels-and-target-fit.md`, §3, line 64: "`numeric-selection.md` currently specifies **level 3 only.**" Research. Custom posit synthesis from ranges: dts-dmm-paper.md, §6.5, line 520. Research.

**Tensions.** Uncovered range is a Warning in the paper and a hard error in the spec. dts-dmm-paper.md, §2.6, line 176: "Warning: posit<32, es=2> dynamic range [1e-36, 1e36] does not cover". numeric-selection.md, line 52: "A non-covering format SHALL NOT be selected." The paper is authority and its block is a design-sketch diagnostic; the spec's hard-error rule is the refinement the paper would need to admit. Signedness in the FPGA example: fixed-point-scaffolding.md line 321 sign-extends a `[0, 1023]` value while lines 338 and 342 treat it unsigned; the spec rule at width-inference.md line 33 makes it unsigned. Where the representation is fixed: fixed-point-scaffolding.md line 59 says the elaborator, line 61 says lowering reads the coeffect; the spec resolves this at width-inference.md line 58. Range-driven selection is evidenced for FPGA integer widths only, fixed-point-scaffolding.md line 311 against Appendix A line 267. The word "seal" in the FHE notes means encryption, `/home/hhh/repos/arxiv-papers/research/FHE-modeling/03-bounds-as-witnesses.md`, line 17; it is not the width seal.

## T4. Discharge fragments, emission gates, and the tier

**What the corpus designs.**

The bound itself is computed, not decided. numeric-selection.md, §4, line 115: "its bound `[a, b]` is obtained by **directly evaluating the expression in the outward-rounded interval domain of §9.1 — an image computation, not a satisfiability query handed to a decision procedure.**" Design-decision. Same line: "Every downstream obligation that *is* discharged as a formula lands in the linear-integer / bit-vector fragment (`QF_LIA` / `QF_BV`) the framework already commits to." Design-decision. The carried object is categorical, §4, line 111: "What the selector produces and freezes onto the PSG is a point in a **bounded, enumerable representation lattice**". Design-decision.

Integer range facts are Tier 2 obligations. fixed-point-scaffolding.md, Appendix C, line 329: "The fact the analysis computed, `%wrap` in $[0,1023]$, is a proof obligation, and it is a bitvector case: a Tier 2 obligation in the QF_BV fragment, the fragment that carries word-width reasoning." Design-decision. Solver discharge of that fact is proposed, not built. Line 355: "The width inference and the truncation are in the middle end today. The SMT-dialect obligation is a proposed addition". Design-sketch.

Bounds sit at Tier 2 as a family. decidable-by-construction.md, §5.3, line 229: "| Tier 2: QF_LIA, QF_LRA, QF_BV | Bounds, invariants, rational-exponent obligations, bit-level properties | NP-complete (conjunctive fragments lower) | Computable |". Design-decision. Members are incomparable, line 236: "integrality is not expressible over the reals, and rationals are not expressible over the integers." Design-decision. The spec admits the ladder. `/home/hhh/repos/clef-lang-spec/spec/terms-and-definitions.md`, line 104: "Tier 2 is quantifier-free linear obligations (integer `QF_LIA`, real `QF_LRA`) and bit-vector obligations (`QF_BV`); Tier 3 covers termination/probabilistic-bounded obligations". Normative.

Real-sorted nonlinear obligations enter Tier 2 as a named subfragment. `/home/hhh/repos/arxiv-papers/negative-fractional-types-in-fidelity.md`, §8.3, line 286: "The rotor-normalization and gate-unitarity obligations our companion papers carry are real-sorted and quadratic, and they occupy the same tier as decidable solver-discharged members". Design-decision. Unrestricted QF_NRA is excluded by an emission gate. `/home/hhh/repos/arxiv-papers/research/Recommendation_from_Fable_Chat/real-sorted-fragment-design-draft.md`, §3, line 63: "The framework does not admit QF_NRA. It admits a named subfragment." Design-sketch. §4, line 87 onward: "The fragment is enforced at emission, not discovered by the solver." and "An obligation failing any condition is a design-time error at the source location". Design-sketch. The integer side must stay linear. decidable-by-construction.md, §8, line 321: "No construct in the framework emits a nonlinear integer constraint". Normative.

Real-sorted discharge cannot yet route through MLIR. `/home/hhh/repos/arxiv-papers/research/grade-axis/04-paper-amendment-schedule.md`, §D.3, line 264: "The MLIR SMT dialect has no Real sort." Implemented-claim. Interim: "real-sorted discharge happens in CCS against the PSG while integer and bit-vector obligations take both paths." Design-decision.

Trusted base. fixed-point-scaffolding.md, §3, line 49: "a deployment that needs safety-critical arithmetic and range proofs accepts a smaller base than one that needs the relational, probabilistic proofs of Tier 4." Normative. Witness form may be an unsat core, §6, line 184. Normative.

Escalation. An untightenable bound is a conservative finding and ascends a tier. fixed-point-scaffolding.md, §5, line 160: "when a lower tier cannot tighten a bound, the framework performs the shift $\uparrow_{k,k+1}$". Design-sketch.

**What it leaves open.** Which member a real range containment obligation takes when it does form a formula, since the spec routes everything to QF_LIA/QF_BV by classification; silent. The quadratic fragment's complexity bound, 04-paper-amendment-schedule.md, §H.2, line 419: "The adiabatic obligation is an **inequality**. Check the extension before quoting the bound". Research. The emission gate's diagnostics are held for a spec chapter, §I, line 433: "The full quadratic real fragment specification, its emission gate, and its diagnostics. A specification chapter, not paper material." Design-sketch.

**Tensions.** dts-dmm-paper.md, §6.8, line 542 names QF_LIA alone. decidable-by-construction.md names QF_LIA/QF_LRA/QF_BV at Tier 2 and its Theorem 2.1, line 33, lists "numeric representation adequacy" among Tier 1 properties while its Table 2 lists no range axis at Tier 1. The amendment schedule records the disagreement at §A.8, line 104. The spec's own position is that the range is not a solver object at all, numeric-selection.md line 115. Resolution by authority: the papers govern the tier ladder, the spec governs the classification route; both agree ranges are never Tier 1 free theorems. A vocabulary collision stands: numeric-selection.md "Tier 1/2/3" are range provenances mapped to inference Levels 1 to 3, line 70, while the papers' Tiers 1 to 4 are verification strength. The two ladders share a word and nothing else.

## T5. The distribution end

**What the corpus designs.**

The site post states the continuum. beyond-the-bitter-lesson-structural-convergence.md, line 74: "The same machinery types a distribution over values as readily as a single value, an object you compose by the same rules. A point reference is the degenerate case of that object, a spike with all its mass in one place." Site, tier 3 authority. Line 76: "The point-value is the special case, the one where the variance went to zero." Line 88: "Distributions collapse to point masses, the Kleisli category collapses to relations, the coend collapses to relational composition, and Bayes becomes *modus ponens*." Line 110: "drawing that prior into the type, so construction and probability are one object, is the next stretch of our grade-axis work." Aspirational by its own words.

What the papers design is narrower and lives in three places.

First, distributions as Tier 3 solver content. fixed-point-scaffolding.md, §3, line 46: "| 3 | restricted probabilistic | solver with library lemmas | distributions on lattice cosets | SMT solver |". Design-decision. Distributional facts are never free, §9, line 246: "the free-theorem boundary of Section 6 forbids distributional and relational facts being free of any type discipline". Normative.

Second, the prior as the type's support over model parameters. `/home/hhh/repos/arxiv-papers/adaptive-domain-models.md`, §3.4, lines 166 to 170: "p(W) \propto \mathbf{1}[W \in \mathcal{W}_{\mathrm{adm}}] \cdot \tilde{p}(W),$$ where $\tilde{p}(W)$ is a density over $\mathcal{W}_{\mathrm{adm}}$ and the indicator is exact, not a penalty." Design-sketch. The locus is parameters, not values.

Third, conditioning as a fractional demand. negative-fractional-types-in-fidelity.md, §10, line 312: "The fractional type `Recip<Evidence>` would be the type-level representation of the conditioning obligation." Design-sketch. Its `Distribution<'T>` is a wrapper type, lines 315 to 326, never defined, and probabilistic structure is placed at "Tier 3 distributional refinement", §11, line 367. Design-sketch.

The spec confines distribution knowledge to a library and keeps the selector exact. numeric-selection.md, §4, line 140: "A genuinely distribution-*weighted* objective — integrating expected error against an activation density rather than scoring a skewed range's worst case — remains a possible future refinement scoped strictly to the ML domain library". Design-decision. Drift is folded into the range, §1, line 18: "the *expected drift is part of the range*; the margin is sized to it." Normative.

The interval as projection of a posterior is stated once, in a research note. `/home/hhh/repos/arxiv-papers/research/geometric-interchange/03-the-posterior-on-the-wire.md`, line 23: "The published Confidence field is an Interval, which is a cheap projection of a distribution and not a full covariance". Implemented-claim, directional. The proposed shape of a distribution-typed value, line 13: "A Gaussian over a graded manifold factors into a mean and a covariance, and the covariance lives in the tangent space of the manifold at the mean." Design-sketch, directional.

The paper's MAP reading is over type assignments, not values. decidable-by-construction.md, §8, line 317: "the $\mathbb{Z}^n$ prior is over dimensional and grade assignments." Normative.

**What it leaves open.** A posterior carried by a numeric type: not designed in any paper or spec chapter. The Kleisli and profunctor reading appears only in the site post, lines 86 to 88. Priors as constraints on a value type: silent. Non-Gaussian posteriors: 03-the-posterior-on-the-wire.md line 23 scopes the sketch to Gaussian. Coherence metrics between type and distribution: adaptive-domain-models.md, §9, line 392. Research.

**Tensions.** The site places the prior-in-type on the grade axis, line 110. The papers place distributions on the verification-strength axis at Tier 3, fixed-point-scaffolding.md line 46, and the coexponential note keeps them out of the type connective, `/home/hhh/repos/arxiv-papers/research/coexponential-inference/04-inference-ladder-design.md`, line 81: "never in the operational calculus and never as a formal sum". The papers govern. The site's claim is aspirational by its own framing, and the corpus is consistent that today the distribution is solver content or library content, not type content. The PHG paper draws the proof boundary explicitly, program-hypergraph-paper.md, §6.4, line 330: "require runtime verification or probabilistic guarantees".

## T6. Surface syntax and its status

Ranged integer sketch on the site. `/home/hhh/repos/clef-lang-site/hugo/content/blog/fidelity-framework-primer.md`, line 77: "type RangeInt<[<Measure>] 'Min, [<Measure>] 'Max>". Dual constructors, not range syntax. negative-fractional-types-in-fidelity.md, §6, line 118: "the additive dual would be written `Neg<'T>` or, in infix algebraic notation, `-'T`. We're considering the multiplicative dual could be written `Recip<'T>` or `1/'T`." Design-sketch.

Interval enclosure type. rounding.md, §3.1, line 44: `Interval<r>`. Normative, but a value type, not range syntax.

**Status summary.** Seal form: not yet specified, critical path. Ranged real: named, not specified. `RangeInt`: site sketch, unadmitted. `Range(lo, hi)`: illustration. Distribution wrapper `Distribution<'T>`: used, never defined.

## T7. The continuum, stated

The axis the Bitter Lesson post names runs from exact constructed structure to statistically arranged structure, beyond-the-bitter-lesson-structural-convergence.md line 48, and the numeric type occupies it three times over. A point type is a value whose interval has width zero and whose posterior has variance zero. The spec admits the first identity for integers, width-inference.md line 22, where a literal is the interval `[a, a]`; a real literal has no such statement, though the same real interval domain runs over every real, numeric-selection.md line 169. The site admits the second identity, line 76, and no paper or spec chapter does. A ranged type is a value whose interval has positive width; its representation is chosen by the argmin and its width by the log formula, so the point representation `int32` or `float64` is what selection produces for a range that is wide or unobservable, native-type-universe.md line 176, and not a type in its own right. A distribution-carrying type is a value whose mean is the point and whose spread is a second object of the same grade, 03-the-posterior-on-the-wire.md line 13, and its interval is the projection of that spread, line 23. The three occupy three verification tiers: dimensional equality on the point is Tier 1 and free, an interval claim is Tier 2 and solver-discharged, a distributional claim is Tier 3 and lemma-assisted, fixed-point-scaffolding.md line 186 and ohori-proof-theory-and-our-tier-architecture.md line 44.
